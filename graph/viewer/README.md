# 离线交互剧情图

双击 `graph/story_graph_viewer.html`，用 Chrome 或 Edge 打开，拖入剧情 JSON。依赖已打入 HTML，不需要网络或本地服务；支持 schema v2、v3 的完整 StoryGraph 和对应 narrative 文件。

默认显示一张连续的玩家剧情图。它保留玩家选择及地点导航形成的自由探索区域；分支条件和变量变化写在连接上。普通对白、Ren'Py 的判断、跳转、汇合、调用和界面内部代码折叠在详情中，保留原文及来源。

同一个选择的分支会横向排列。即使不同答案通往同一个后续选择，也保留各自的箭头、条件、影响和详情，共同的后续选择只画一次。悬停或选中的选择，其直接相连的路径会显示，其它节点保持可见。所有向前分支直接连接实际后续节点，跨越中间选择的路线使用独立通道绕开节点和文字，不再使用紫色短跳转框。回到前面选择的箭头仍连接实际目标，返回框不预留布局空间。悬停或选中返回目标时，汇入的返回线统一淡化并收起说明框，右侧详情列出全部返回路径。悬停连接较少的来源节点或逐条选中返回线，可突出显示对应说明。文字框与线相交时，焦点路径的说明置顶。重新尝试当前选项的去向保留在详情中，不画自环。

起点、终点都相同的返回分支共用一个返回框和一条箭头，框中列出不同回答及条件。点击返回框可分别查看每个分支的影响、对白和来源，再通过「返回上一级」回到分支列表。不同起点或不同终点的返回线分别保留。

正常路径从节点底部出线、从后续节点顶部进入，使用小圆角直角折线；上下对齐的单条续接直接画直线。分叉位于选项文字之前，每个答案沿自己的纵向路径进入实际目标，只有进入共同后续时才汇合。小圆点标明真实分叉或汇合；小拱线表示两条路径交叉但并未汇合。排层依据实际剧情连接的前后顺序，不按最短距离或固定画布宽度换行；只有构成循环的回边才作为返回显示。返回线连接目标最近的轮廓位置，必要时局部绕开其它节点。同排分支返回共同父选择时，返回框按分支顺序排在同一行，对称分支保持镜像连线；每条路线仍可分别点击。

玩家图依据 Ren'Py 的标准 `_in_replay = None` 正常游玩状态，移除只在回放中执行的设置、选项及变量影响。共享场景和其它独立剧情仍保留；检测不依赖游戏名称、文件名或标签名称。游戏明确改写 `_in_replay` 时保留其原始流程，自定义回放变量也保持原样。源文件视图及原始条件、对白和来源不受影响。选择编号保持稳定，因此回放选项被移除后编号可能不连续。

连续的脚本判断折叠到连接上的条件中。多条答案需要共用同一个分流入口时，只显示一个小连接点；点击可查看其来源。紫色「自由探索」表示通过地点界面进入不同剧情的区域，点击可以查看可到达的选择、触发条件和区域内活动。它按界面之间的实际连接识别，不按源文件划分；探索区的去向不会复制到之前的每个答案下面。仅改变背景对白的判断保留在详情中。

菜单没有标题时，菱形优先使用同一前序链上的最近对白作为剧情提示；找不到对白才回退到选项原文，避免整张图出现大量相同的“继续 / 返回”标题。

- 拖动平移、滚轮缩放；「查看完整剧情图」按宽度进入可读总览并从入口开始，「从第一个选择开始」回到入口局部视图。
- 选项文字、条件和变量变化写在分支线上；点击分支查看完整条件、变量表达式、折叠对白、来源及被省略的内部控制流。
- 右下缩略图显示全图、当前视野和位置标记；拖动视图框可连续移动视角，点击其他位置可直接跳转。返回线随悬停或选中动态显示，不改变底图。拖动左右侧栏边缘可调整宽度，布局会在本机记住。
- 左侧选择目录和顶部搜索只负责定位，不切换剧情页面或重新布局。可输入 `6`、`选择 6`、`#6` 查找编号；文本搜索高亮命中的对白、选项、变量或位置。点击结果外的区域关闭结果列表。
- 点击选项后，右侧「返回上一级」可以回到选项总览，并恢复之前的滚动位置。选中或取消选中不会改变相机。两侧栏收放有短动画，支持系统的减少动画设置。
- 在详情点击「设为当前位置」保存当前位置；「回到我的位置」返回标记。查看器不会实时读取游戏进度。
- 「源文件」是开发者辅助视图，保留脚本结构、调用和来源追溯；玩家主图不按文件组织。

选择后的影响以「启用某特性」「好感增加」「输入姓名、留空时使用默认值」等形式展示，变量名和游戏原文保留。不同答案的去向和条件分开列出。多项影响按执行顺序排列，超过六项可以展开。特殊修改状态下的其它去向另列在可展开的详情中。

图中保留正常游玩的选择，即使它来自不同入口或无法从当前入口静态连通；这种独立剧情段会在同一张长图中上下排列。它们不会被强行画成互相连接的路线。「返回调用处」不显示在玩家画布和小地图中，仍可以在详情或源文件视图中查看。明确结束、重复流程和未解析的后续会分别处理；动态目标、未知操作及原始表达式可以在详情的「开发者信息」中查阅。无法确定的分支仍需结合游戏实际状态判断，查看器不计算最终路线。

## 开发与验证

```powershell
cd graph/viewer
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd run test:browser
node tests/whole-audit.mjs
node tests/performance-smoke.cjs
```

大型样本使用仓库已有的 `tests/semantics/artifacts/phase0-large-game/`，v3 fixture 位于 `tests/semantics/artifacts/acceptance-pale-20260916/`。构建只生成 HTML，不修改游戏、不构建 EXE。`performance-smoke.cjs` 对 Chrome、Edge 的两种文件分别进行一次冷启动及交互抽测；含内存采样的旧 `benchmark.cjs` 本轮未运行。性能实测见 `PERFORMANCE.md`。
